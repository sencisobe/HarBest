5. Migrate existing habits. As the developer, I want existing habits to survive the schema change.

 Existing habits are assigned to a user or removed, with the decision documented
 The app starts cleanly on the migrated database

6. Password reset by email. As a user, I want to reset my password through my email, so that I can recover my account.

 Requesting a reset gives the same response whether or not the email exists
 The email contains a link with a single-use token that expires (e.g. 30 min), stored hashed
 The new password is validated like in registration; the old one stops working
 Works locally with Mailpit and is configurable for a real SMTP

7. Run on local network. As the developer, I want to open the app from another device on my network, so that I can test it like a real user.

 API base URL, CORS origins and frontend URL are configurable, with no hardcoded localhost
 The app works from a phone or another PC on the same network
 The README documents the steps
